# LLM의 실체와 내부 동작 원리

**LLM(Large Language Model, 대규모 언어 모델)** 은 대량의 텍스트에서 언어의 패턴을 학습한 신경망 모델이다. 텍스트 생성형 LLM은 주어진 문맥에 이어질 다음 토큰(텍스트 조각)의 확률을 예측하고, 토큰을 하나씩 선택해 문장을 만든다.

## 1. LLM의 내부는 어떻게 설계되어 있나?

이 글에서는 GPT 계열에서 사용하는 디코더형 Transformer를 기준으로 설명한다. 모델을 구성하는 두 가지는 **계산 구조**와 **학습된 가중치**다.

- **계산 구조**는 벡터의 크기, 층의 개수, 각 층에서 실행할 연산과 그 연결 순서를 정한다. 입력 임베딩, 여러 Transformer 블록, 출력층이 순서대로 연결된다.
- **가중치**는 각 연산에 쓰이는 학습된 숫자다. 입력 임베딩 표, 블록마다 있는 여러 행렬, 출력층의 행렬 등이 여기에 해당한다. 구조가 같아도 가중치가 달라지면 같은 입력에 다른 점수가 나온다.

모델 파일에는 주로 가중치가 저장되고, 구조를 지정하는 설정과 토크나이저 파일이 함께 배포되는 경우가 많다. 추론 엔진은 이를 읽고 구조에 맞는 연산을 실행하는 소프트웨어다. 학습할 때는 예측 오차를 바탕으로 가중치를 조정하고, 일반적인 추론 요청에서는 이미 정해진 가중치를 사용한다.

## 2. 일반 소프트웨어와 LLM의 동작 비교

상품 검색 서비스에 사용자가 **“비 오는 날 들고 다닐 가벼운 우산”**을 입력했다고 가정하자.

| 단계 | 규칙 기반 상품 검색 | 텍스트 생성형 LLM |
|---|---|---|
| 입력 처리 | 검색어를 분석하고 상품 목록에서 후보를 찾는다. | 입력을 토큰으로 나누고 각 토큰을 벡터로 바꾼다. |
| 점수 계산 | 개발자가 정한 규칙을 적용한다. 예를 들어 제목에 검색어가 있으면 10점, 재고가 있으면 2점을 더한다. | Transformer의 여러 층에서 학습된 가중치로 벡터를 변환하고, 어휘표의 각 토큰에 점수를 매긴다. |
| 출력 | 점수순으로 기존 상품 목록을 반환한다. | 다음 토큰 하나를 선택하고, 선택한 토큰을 포함해 다시 계산한다. |

두 시스템 모두 코드가 **계산 순서**를 정한다. 이 예에서 검색 서비스는 **점수 기준을 코드나 설정에 명시**하고, LLM은 **문맥별 후보 점수를 학습된 가중치로 계산**한다.

## 3. 입력이 답변으로 바뀌는 과정

예를 들어 모델에 “비가 와서 우산을”이라는 입력을 주면 다음과 같은 계산이 일어난다.

```text
입력 텍스트 → 토큰 ID → 임베딩 벡터 → Transformer 블록 반복
            → 다음 토큰 후보별 점수 → 토큰 선택 → 다음 생성 단계
```

| 단계 | 무엇이 일어나나 |
|---|---|
| **① 토큰화** | 텍스트를 단어, 단어 일부, 문장부호 등의 조각인 **토큰**으로 나눈다. 각 조각을 어휘표에서 찾을 때 쓰는 정수가 **토큰 ID**다. |
| **② 임베딩** | ID로 임베딩 표의 행을 찾아 **벡터**를 꺼낸다. 벡터는 순서가 있는 숫자 배열이다. 토큰이 10개이고 벡터의 길이가 4,096이라면 입력 표현의 크기는 **10 × 4,096**이다. |
| **③ 문맥 반영** | Transformer 블록마다 **어텐션**이 현재 및 이전 위치의 정보를 섞는다. 예를 들어 “우산” 위치의 벡터에 앞쪽의 “비” 관련 정보가 반영될 수 있다. **피드포워드**는 각 위치의 벡터를 개별적으로 변환한다. |
| **④ 후보 점수 계산** | 출력층이 마지막 위치의 벡터로부터 어휘표 전체의 후보 점수를 만든다. 이 원점수가 **로짓**이다. |
| **⑤ 선택과 반복** | 최고점 토큰을 고르거나, 점수를 확률로 바꿔 샘플링한다. 고른 토큰을 포함해 다음 단계로 넘어간다. |

어텐션 안에서는 현재 위치의 **질의(Q)**와 참조 가능한 위치의 **키(K)**를 비교한다. 비교 점수에 따라 각 위치의 **값(V)**을 얼마나 섞을지 결정한다.

## 4. 왜 GPU 사용량이 큰가?

### 토큰 하나에도 큰 행렬 연산이 반복된다

4,096차원 벡터를 같은 크기의 벡터로 바꾸는 가중치 행렬 하나에는 **4,096 × 4,096 = 약 1,678만 개**의 숫자가 들어간다. 벡터 하나를 이 행렬에 곱하는 데만 약 1,678만 번의 곱셈과 그에 가까운 횟수의 덧셈이 필요하다. 실제 블록에는 어텐션과 피드포워드에 쓰이는 행렬이 여러 개 있고, 이런 블록이 층마다 반복된다. GPU는 한 단계 안에서 독립적인 곱셈과 덧셈을 대량으로 병렬 처리할 수 있다.

### 입력 처리와 답변 생성의 비용이 다르다

- **입력 처리(prefill)**에서는 프롬프트의 토큰을 한꺼번에 계산한다. 입력이 길수록 행렬 연산이 늘고, 모든 앞쪽 위치를 참조하는 기본 어텐션은 입력 길이가 두 배가 되면 토큰 위치 쌍이 대략 네 배로 늘어난다.
- **답변 생성(decode)**에서는 다음 토큰을 고른 뒤에야 그다음 단계로 갈 수 있다. 이전 토큰에서 계산한 어텐션의 키와 값은 **KV 캐시**에 저장해 재사용한다. 새 토큰은 각 블록을 통과하면서 이 캐시를 참조하므로, 앞선 모든 토큰을 처음부터 다시 계산하는 비용을 줄일 수 있다. 문맥이 길어지면 캐시가 차지하는 메모리와 이를 읽는 비용도 커진다.

### 메모리에 담는 양과 읽는 속도도 중요하다

70B 모델의 가중치를 파라미터당 2바이트로 저장하면 **가중치만 약 140GB**다. 실행 중에는 KV 캐시와 작업 공간도 필요하다. 특히 요청 한 건에서 토큰을 하나씩 생성할 때는 큰 가중치 행렬을 매 단계 읽는 데 시간이 많이 든다. 따라서 GPU의 연산 성능과 함께 **메모리 용량**은 모델을 올릴 수 있는지를, **메모리 대역폭**은 가중치와 캐시를 얼마나 빠르게 읽을 수 있는지를 좌우한다.
